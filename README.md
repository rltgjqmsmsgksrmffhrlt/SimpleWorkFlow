# SimpleWorkFlow

8개 과정(매니지먼트/디자인/프론트엔드/백엔드/네이티브/인프라/사이버보안/생성형AI)이 하루 일정과 팀 간 협업을 실시간으로 공유하던 보드입니다.

> **상태: 종료됨.** 더 이상 개발하지 않습니다. 이유는 바로 아래에.

---

## 왜 그만두었나

원래 목표는 **"흩어진 일정을 한 화면에서 다 보기"** 였습니다. 그래서 실시간 동기화, 팀별 간트차트, 종 울리기 협업 요청, WBS 주간 보기까지 만들었습니다.

그런데 마지막에 넣은 기능이 **MD 내보내기**였고, 이게 프로젝트를 끝냈습니다.

일정을 마크다운 양식으로 뽑을 수 있게 되자, 그걸 **노션에 붙여넣는 것만으로 "한 번에 보기"가 해결**됐습니다. 팀이 이미 노션에서 문서를 관리하고 있었으니, 굳이 별도 앱을 켜두고 그 주소로 다 같이 들어올 이유가 없어진 겁니다.

정리하면:

- 필요했던 건 **실시간 협업 도구**가 아니라 **잘 정리된 텍스트 한 덩어리**였습니다.
- 앱이 제공하던 값 중 실제로 쓰인 건 "입력을 구조화해서 예쁘게 뽑아주는 것"이었고, 그건 노션 템플릿이 더 잘합니다.
- 서버를 누군가 켜두어야 하고, 그 사람 PC가 꺼지면 다 같이 못 쓰는 구조였습니다. 노션은 그 제약이 없습니다.

**남길 만한 것**: 붙여넣기 파서(`parsePastedSchedule`)와 MD 내보내기는 앱과 독립적으로 쓸 수 있는 형식이라, 이 저장소에서 가장 오래 쓸모 있을 부분입니다.

**교훈**: "한 화면에서 보기"라는 요구를 *앱을 만들어야 한다*로 읽었지만, 실제로는 *출력 형식을 정해야 한다*였습니다. 내보내기를 먼저 만들었다면 나머지 대부분은 만들 필요가 없었을 겁니다.

## 화면 구성

| 탭 | 내용 |
|---|---|
| **대시보드** | 오늘의 궁극 목표, 전체/과정별 진행률 |
| **오늘 일정** | 세로 간트차트. 과업 등록·수정·상태 관리 |
| **WBS** | 외부 WBS 파일의 주간 보기 (읽기 전용) |
| **협업 요청** | 다른 과정의 종을 울려 회의 요청·조율 |

접속하면 **먼저 본인 과정을 선택**해야 합니다(브라우저에 저장). 일반 과정은 자기 일정만, **매니지먼트 과정은 PM 역할**로 전체를 볼 수 있습니다.

## 오늘 일정 (간트차트)

**조작**

| 동작 | 결과 |
|---|---|
| 빈 곳 드래그 | 그 시간대로 과업 생성 |
| 블록 클릭 | 상태 순환 (시작 전 → 진행 중 → 완료) |
| 블록 우클릭 | 수정 팝업 (이름·시간·하위작업·삭제) |
| 블록 끌기 | 시간 이동 |
| 블록 위/아래 끝 끌기 | 길이 조절 |
| 시/분 위아래 드래그·휠 | 시간 변경 |

모든 시간은 **10분 단위**로 맞춰집니다. 소요시간 프리셋은 1시간/3시간/6시간.

**색상**

- 회색 = 미진행, 초록 = 진행 중, **빨강 = 지연**(종료시간이 지났는데 미완료), 주황 = 미팅 예정, 흐림 = 완료

**고정 일정** — 규칙에서 자동으로 그려집니다(저장하지 않음).

- 점심시간 13:00–14:00 (빗금)
- 팀장 미팅 매일 09:30–10:30
- 전체 미팅 그 주 첫 영업일 15:00–16:00
- 팀장 주간회의 그 주 마지막 영업일 16:00–17:00

주말과 한국 공휴일은 영업일에서 제외됩니다. 공휴일 목록은 `client/src/schedule-rules.js`에 **2026-10-09까지만** 들어 있으니, 이후로 쓰려면 날짜를 추가해야 합니다.

**열 나누기** — 한 과정 안에서 병렬 작업을 나눠 보려면 `+`로 열을 추가합니다(`추가 열1`, `추가 열2`…). 빈 열은 `×`로 지울 수 있습니다. PM이 전체 과정을 볼 때는 열이 접힙니다.

**담당자** — `server/members.js`의 21명 명단에서 고릅니다. 하위작업이 있으면 하위작업마다, 없으면 과업 자체에 담당자가 필요하고, 비어 있으면 빨간 경고가 붙습니다(저장은 막지 않음).

## 붙여넣기 등록 / MD 내보내기

**붙여넣기로 추가** — 회의록이나 WBS에서 복사한 텍스트를 그대로 받습니다.

```
`09:30 ~ 09:50` 데일리 스크럼      → 09:30–09:50 데일리 스크럼
- 10:00 팀 회의                    → 10:00–11:00 (다음 줄 시작까지 자동)
    안건 정리                      → ↑의 하위작업
  11:00-12:00 코드리뷰             → 11:00–12:00 코드리뷰
```

백틱·불릿·번호·체크박스를 걷어내고, `~ - – —` 어떤 구분자든 받습니다. 끝시간이 없으면 다음 줄 시작까지, 마지막 줄이면 1시간. 들여쓴 줄은 하위작업.

파서가 관대한 대신 **등록 전에 미리보기로 확인**합니다. 인식 못 한 줄도 버리지 않고 회색으로 보여줍니다.

**MD로 내보내기** — 오늘 일정과 WBS 주간을 마크다운으로 뽑습니다(복사 / `.md` 다운로드).

```markdown
## 백엔드

- [ ] `09:30 ~ 09:50` 데일리 스크럼 — 문시원
- [ ] `10:00 ~ 11:30` API 설계
    - [ ] 스키마 확정
```

이 형식은 위 파서가 읽는 형식과 같아서 **내보낸 걸 다시 붙여넣을 수 있습니다**. 다만 담당자(`— 이름`)는 재등록 시 제목에 흡수되고, `## 고정 일정` 섹션째로 붙여넣으면 자동 생성되는 회의가 진짜 과업으로 중복 등록됩니다.

## 협업 요청

종을 울리면 **입력 없이 즉시** 상대 과정에 알림이 갑니다(소리 + 배너). 같은 상대에게 다시 울리면 새 카드가 아니라 기존 카드에 재알림 횟수가 쌓입니다.

역할이 나뉘어 있습니다:

| 항목 | 정하는 쪽 |
|---|---|
| 장소 (디스코드/Zep + 방 번호) | 요청한 과정 |
| 안건 | 요청한 과정 |
| **시간** | 요청받은 과정 |

**요청받은 쪽이 시간을 넣는 순간 확정**됩니다. 확정되면 **양쪽 과정의 간트차트에 1시간짜리 주황 블록**이 생깁니다. 이 블록은 따로 저장되지 않고 협업 요청에서 바로 그려지므로, 시간을 고치면 양쪽이 같이 움직입니다.

## WBS

`WBS` 폴더(exe와 같은 위치)의 **가장 최신 JSON**을 읽어 주간으로 보여줍니다. 이전/다음 주 이동 가능.

**읽기 전용입니다.** 편집은 https://rad-babka-6c8427.netlify.app/ 에서 하고, 내보낸 JSON을 `WBS` 폴더에 떨어뜨리면 앱 새로고침만으로 반영됩니다(재빌드 불필요).

과정별 열람 제한은 일정과 같습니다. 담당 과정이 없는 `준비` 파트는 전원에게 보입니다.

## 실행

### 배포용 exe

```bash
cd server
npm install
npm run package
```

`SimpleWorkFlow-dist/SimpleWorkFlow.exe`(약 110MB)가 만들어집니다. 이 파일 하나만 전달하면 Node.js 없이 실행됩니다.

더블클릭하면 서버 실행 → 공개 터널 연결 → 브라우저가 **공개 주소로** 열립니다. 데이터는 exe 옆 `data.json`에 저장됩니다.

### 주소 고정 (무료)

기본은 켤 때마다 주소가 바뀌는 임시 터널입니다. 고정하려면:

1. **Microsoft Store**에서 `ngrok` 설치
   공식 사이트에서 exe를 직접 받으면 **Windows Defender가 `Trojan:Win32/Kepavll!rfn`으로 오탐해 삭제합니다.** 반드시 Store 버전을 쓰세요.
2. authtoken 등록 (한 번만):
   ```bash
   ngrok config add-authtoken 여기에_본인_토큰
   ```
   `$YOUR_AUTHTOKEN`을 그대로 붙여넣으면 PowerShell이 빈 값으로 치환하니, 실제 토큰으로 바꿔야 합니다.
3. exe를 한 번 실행하면 생기는 `ngrok-domain.txt` 맨 아래에 도메인을 한 줄로 적습니다:
   ```
   lymphatolytic-suitably-derick.ngrok-free.dev
   ```
   도메인은 https://dashboard.ngrok.com/domains 에 **이미 발급되어 있습니다**(`dev domain` 배지). 계정당 1개, 이름 변경 불가, 만료 없음. "New Domain"으로 새로 만드는 건 유료입니다.

설정이 없거나 ngrok 실행이 실패하면 임시 터널로 자동 대체되므로 앱이 안 뜨는 일은 없습니다.

무료 플랜 제약: **월 1GB 전송량**(번들이 gzip 75KB라 30명이 한 달 써도 여유), **첫 접속 시 경고 페이지 1회 클릭**(이후 7일간 안 뜸).

### 여러 조직에 나눠줄 때

조직이 다르면 데이터가 섞이면 안 되므로 **조직마다 exe를 따로 돌립니다.**

- 한 조직 안에서는 **1명만** exe를 켜고 나머지는 그 주소로 접속합니다. 그래야 과정 간 협업 종이 통합니다.
- 다른 조직에는 exe를 건네고, 그쪽에서 각자 ngrok 계정으로 주소를 고정합니다.

### 개발

```bash
cd server && npm install && npm run dev   # :4000  API + Socket
cd client && npm install && npm run dev   # :5173  화면
```

개발 시 데이터는 `server/data.json`, WBS는 `server/WBS/`를 읽습니다.

## 데이터

모든 데이터는 서버를 켠 컴퓨터의 `data.json` **한 파일**에 저장됩니다. DB 없음.

- 목표·과업·협업 요청은 **날짜별로 저장**되고 화면에는 오늘 것만 보입니다. 지난 기록은 파일에 남아 있지만 화면에서 다시 볼 방법은 없습니다.
- 과업 스키마 변경은 `server/store.js`의 `migrateTasks()`가 불러올 때 백필합니다.

- **지난 날짜 조회** — 데이터는 남아 있으나 화면이 없습니다.
